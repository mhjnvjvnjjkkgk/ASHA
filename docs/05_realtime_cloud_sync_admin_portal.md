## ⚡ 1. Dual-App Real-Time Sync Topology

ASHA consists of two independent web applications operating in real-time synchronization:
1. **Citizen Emergency Web App (`ashaien.vercel.app`)**: Used by patients or bystanders to triage symptoms, route to hospitals, place 15-minute soft-holds, view live Situational First-Aid protocols, and obtain their 4-digit OTP.
2. **Hospital ER Desk Portal (`ashaien-admin.vercel.app`)**: Used by ER nurses and administrative staff to manage shift staffing, bed inventory, blood banks, and verify 4-digit OTP admissions in under 2 seconds.

## 🗄️ 2. Relational Database Schemas & Realtime Tables (Supabase)

ASHA utilizes **Supabase (PostgreSQL 15)** with real-time replication enabled on all core tables:

### Table 1: `public.active_holds`
Tracks active 15-minute soft-lock reservations generated by citizens.

```sql
create table public.active_holds (
  hold_id text primary key,
  hospital_id text not null,
  otp text not null, -- 4-digit numeric verification OTP
  patient_name text default 'Emergency Patient',
  symptom text default 'Acute Triage',
  ward_code text default 'general_oxygen',
  locked_at timestamp with time zone default now(),
  expires_at timestamp with time zone not null,
  status text default 'ACTIVE' check (status in ('ACTIVE', 'ADMITTED', 'CANCELLED')),
  vector_status text default 'TOWARD'
);

-- Enable Realtime Replication
alter publication supabase_realtime add table public.active_holds;
```

### Table 2: `public.admitted_patients`
Logs patients who have been verified by 4-digit OTP and admitted at the ER desk.

```sql
create table public.admitted_patients (
  id text primary key,
  hospital_id text not null,
  patient_name text not null,
  symptom text not null,
  ward_code text not null,
  ward_label text not null,
  admitted_at timestamp with time zone default now(),
  otp text not null
);

-- Enable Realtime Replication
alter publication supabase_realtime add table public.admitted_patients;
```

### Table 3: `public.hospital_overrides`
Stores dynamic operational capacity overrides published by ER nurses.

```sql
create table public.hospital_overrides (
  hospital_id text primary key,
  available_beds integer,
  total_nurses integer,
  ward_beds jsonb,
  blood_stock jsonb,
  updated_at timestamp with time zone default now()
);

-- Enable Realtime Replication
alter publication supabase_realtime add table public.hospital_overrides;
```

## 📡 3. BroadcastChannel Fallback for Local Inter-Tab Sync

When testing or operating both the Citizen App and Hospital Admin Desk on the same physical computer or local network, ASHA layers an **HTML5 BroadcastChannel API** fallback over WebSockets:

```typescript
// Inter-tab synchronization in cloudDb.ts
const channel = new BroadcastChannel('asha_sync_channel');

channel.onmessage = (event) => {
  if (event.data && event.data.type === 'HOLD_UPDATED') {
    // Reload local state instantly across browser tabs
    loadDataFromCloudDb();
  }
};
```

## 🧮 4. The "Staffed Bed vs. Ghost Bed" Mathematical Engine

A critical systemic failure in traditional emergency dashboards is displaying physical bed frames that cannot accept patients because no nurses are assigned to staff them (**Ghost Beds**).

ASHA mathematically calculates **Staffed Bed Capacity** based on active nurse staffing levels:

### Nurse-to-Patient Clinical Standard Ratios:
- **Intensive Care Unit (ICU / Cardiac ICU):** $1 \text{ Nurse} : 1 \text{ Patient}$ ($R_{\text{ICU}} = 1.0$).
- **Pediatric ICU (PICU):** $1 \text{ Nurse} : 2 \text{ Patients}$ ($R_{\text{PICU}} = 0.5$).
- **General Ward (General Oxygen):** $1 \text{ Nurse} : 6 \text{ Patients}$ ($R_{\text{General}} = 0.166$).

### Capacity Equations:

$$\text{Nurse Capacity} = \lfloor \text{Active On-Duty Nurses} \times R_{\text{Ward}} \rfloor$$

$$\text{Staffed Beds} = \min(\text{Total Physical Beds}, \text{Nurse Capacity})$$

$$\text{Available Beds Now} = \max(0, \text{Staffed Beds} - \text{Occupied Beds} - \text{Active Holds})$$

$$\text{Ghost Bed Gap} = \text{Total Physical Beds} - \text{Staffed Beds}$$

*Example:* If a hospital has 30 physical ICU beds but only 5 on-duty nurses, ASHA calculates **Staffed Beds = 5**, restricting public soft-locks to 5 and flagging **25 Ghost Beds**.

## 🖥️ 5. Hospital Admin Portal Control Systems (`ashaien-admin.vercel.app`)

The Hospital Admin Portal is designed specifically for high-stress triage environments with **Zero Cognitive Overhead**:

1. **Tab 1: BEDS (Nurse & Ward Management):**
   - Shift Nurse Adjuster (`+` / `-`). Updating active nurses automatically re-calculates staffed bed limits across all 4 wards in real-time.
   - Ward Bed Counters (`+` / `-`) for General Ward, Cardiac ICU, Adult ICU, and PICU.
2. **Tab 2: BLOOD (Transfusion Inventory):**
   - Live counters for `O-`, `O+`, `A+`, `B+`, `AB+`, `A-`, `B-`, `AB-` across PRBC, Platelet, and Plasma reserves.
3. **Tab 3: ADMITTED LOGS:**
   - Real-time log of checked-in patients with a one-tap **"DISCHARGE PATIENT (UNLOCK BED)"** button that restores bed capacity live.
4. **Tab 4: HOLDS QUEUE:**
   - Displays live incoming patient holds, triaged symptoms (e.g., *"buke betha"* / Acute Chest Pain), countdown timers, and 4-digit OTP passcodes.
5. **Patient Check-In & Bed Admission Terminal:**
   - Nurse enters the patient's **4-digit OTP** (spoken aloud by bystander/paramedic).
   - Selects target ward bed.
   - Taps **"VERIFY OTP & ADMIT PATIENT"** to execute the hard-lock admission in under 2 seconds.
